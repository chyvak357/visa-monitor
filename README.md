# Монитор слотов на визу — Посольство Франции в Тбилиси

Следит за свободными слотами на подачу документов (краткосрочная виза) на consulat.gouv.fr
и присылает их в Telegram. Работает у вас на компьютере: сам открывает Google Chrome,
проходит запись до календаря и раз в пару минут проверяет выбранный диапазон дат.

## Что нужно

- macOS или Linux
- [Google Chrome](https://www.google.com/chrome/)
- [Node.js](https://nodejs.org) 20 или новее (на macOS — установщик LTS с сайта или `brew install node`)
- Telegram

## Установка

В терминале, в папке проекта:

```sh
npm install
npm run setup
```

Мастер настройки:

1. Проверит Node.js и Chrome.
2. Попросит создать своего бота: в Telegram откройте **@BotFather** → `/newbot` → придумайте имя →
   вставьте в терминал токен, который он пришлёт.
3. Попросит нажать **Start** в вашем новом боте — так он сам узнает, куда слать алерты.
4. Спросит, в каком диапазоне дат искать слоты.

## Запуск

```sh
npm start
```

Откроется окно Chrome — его **не закрывайте** (можно свернуть или увести на другой рабочий стол).
Остановить — `Ctrl+C` в терминале.

Компьютер не должен засыпать:

- macOS: `caffeinate -i npm start` (у ноутбука при этом нельзя закрывать крышку)
- Linux: `systemd-inhibit npm start`

## Настройки

Всё в файле `.env`, правки подхватываются без перезапуска:

| Параметр | Что значит |
|---|---|
| `DATE_FROM`, `DATE_TO` | Диапазон дат для поиска, `ГГГГ-ММ-ДД` |
| `POLL_SECONDS` | Как часто проверять, секунд (по умолчанию 120 — чаще не стоит, сайт ограничивает частоту) |
| `POLL_MIN_SECONDS` | Ускорение опроса: после каждой удачной проверки интервал сокращается к этому значению, при 429 откатывается к `POLL_SECONDS`, и до перезапуска ниже уже не опускается. По умолчанию равен `POLL_SECONDS` — без ускорения |
| `HOLD_AFTER_ALERT_MIN` | После алерта окно робота N минут стоит на календаре — можно бронировать прямо в нём. `0` — не держать |
| `BOOKING_MODE` | `alert` (по умолчанию) — алерт с кнопками, записывает робот по нажатию. `auto` — робот записывает сам, сразу как нашёл слот, см. «Автозапись» |
| `BOOKING_DRY_RUN` | `1` — запись всё заполняет, но не подтверждает (для проверки). `0` — записывает по-настоящему |
| `FRESH_BROWSER` | `1` (по умолчанию) — перед каждой новой сессией перезапускать Chrome, капча так реже просит человека. Запись по найденному слоту всё равно идёт в том же окне. `0` — всё в одном окне |
| `CAPTCHA_AUTOCLICK` | `1` (или `npm start -- --autoclick`) — если капча не прошла сама, робот сам кликает по галочке, пока вас нет у компьютера. С `NESTED_DISPLAY` клик настоящий, курсором Xephyr через `xdotool` (`sudo apt install xdotool`); ваша мышь при этом не двигается. Без Xephyr — клик через DevTools, его капча распознаёт чаще |

## Автозапись

Если заполнить `people.json`, в алертах появятся кнопки со слотами: нажали на слот → выбрали,
кого записать → робот сам выберет время, заполнит форму и подтвердит запись. Один человек — один слот;
«Всех по порядку» записывает людей из списка на выбранный слот и следующие за ним.

```sh
cp people.example.json people.json   # и вписать свои данные
```

| Поле | Что писать |
|---|---|
| `name` | Как подписать кнопку в Telegram |
| `lastname`, `firstname` | Как в загранпаспорте |
| `email` | Сюда придёт подтверждение от посольства |
| `phone` | С кодом страны: `+995555123456` |
| `birthdate` | `ДД.ММ.ГГГГ` |
| `purpose` | Цель поездки: `туризм`, `семья`, `деловой`, `учёба` (как в списке на сайте) |

Проверить данные без записи — пробный прогон: всё заполняется, но «Подтвердить» не нажимается
(монитор на это время остановите):

```sh
npm run book -- --person 1 --date 2026-12-28 --time 09:30
```

В `.env` то же самое включает `BOOKING_DRY_RUN=1` — для кнопок в Telegram. Когда убедились, что форма
заполняется правильно, поставьте `BOOKING_DRY_RUN=0`.

### Без кнопок: `BOOKING_MODE=auto`

Робот записывает сам, как только в диапазоне появился слот: календарь уже открыт, так что счёт идёт на секунды.
Каждого, кто ещё не записан, — на свой слот, начиная с самого раннего; занят — берёт следующий.
Алерт подписчикам уходит параллельно, без кнопок. Опрос на время записи останавливается.

Кто записан, хранится в `data/booked.json` и после перезапуска не записывается повторно — ни автоматически,
ни по кнопке. Если «Подтвердить» нажата, но сайт ответил ошибкой, человек тоже считается записанным
(со знаком «?» в `/status`): проверьте почту и, если записи нет, удалите его из `data/booked.json`.

Сначала стоит погонять с `BOOKING_DRY_RUN=1`: робот будет проходить всё, кроме последней кнопки.
Учтите, что выбранный слот на несколько минут скрыт от других, — пробный прогон его тоже придерживает.

Если сайт после подтверждения попросит код из письма — бот спросит его в чате.
Если во время «удержания окна» выбрать время в окне робота руками, бот предложит дозаполнить форму за нужного человека.

## Telegram

- `/status` — что сейчас с мониторингом и какие слоты открыты.
- Чтобы алерты получал ещё кто-то, пусть откроет вашего бота и нажмёт **Start** —
  вам придёт запрос с кнопками «Пустить / Нет». `/stop` — отписаться.
- Сообщения об ошибках и капче приходят только владельцу бота.

## Статистика

Монитор пишет каждое наблюдение в `data/observations.jsonl` (строка JSON на событие, время в UTC) —
чтобы потом понять, когда и на какие даты освобождаются слоты. `scan` — успешная проверка:
окно записи, все дни окна без мест (`excluded`) и время с `capacity` по дням с местами (`timed`:
весь диапазон на каждой проверке плюс до 5 дней вне его — их время смотрим сразу, как день открылся,
дальше раз в минуту, и в алерты они не попадают);
`fail`, `start`, `stop` — когда мы не смотрели; `book`, `hold` — собственные действия робота.
Выходит меньше 1 МБ в сутки.

## Если что-то не так

- **«Капча не проходит сама»** — в Telegram придёт скриншот; пройдите капчу в окне робота, дальше он сам. Если за 2 минуты никто не прошёл, робот перезапускает браузер — после этого капча часто проходит сама (до 3 перезапусков подряд). Перед этим робот сам пару раз перезапускает виджет капчи, не перезагружая страницу. Если капча застряла на последнем шаге записи, выбранный слот не теряется: после перезапуска робот ждёт, пока сайт отпустит его от брошенной сессии (до 7 мин), и сразу забирает.
- **«N раз подряд не получается проверить слоты»** — посмотрите на скриншот и лог в терминале.
  Ошибка `429` значит, что сайт временно ограничил частоту запросов: монитор переждёт сам.
- **«этого бота уже слушает другой процесс»** — запущено два монитора с одним ботом
  (или монитор и `npm run setup` одновременно). Оставьте один.
